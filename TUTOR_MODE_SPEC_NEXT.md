# Tutor Mode — ближайшая итерация (спека перед реализацией)

Статус: **черновик для реализации**, не полный редизайн.
Полный редизайн (единый промпт, отказ от Recasting/Mistakes Practice как
тумблеров и т.п.) остаётся в `roadmap.md` как отдельная будущая задача —
здесь только то, что решено делать прямо сейчас.

Контекст: разбор репозитория выявил ряд багов (пустые re-engagement
сообщения, сломанный HTML в Deep Dive, отсутствие "✅ Правильно" в отчёте
и др. — см. отдельное обсуждение/issues) и стал поводом пересмотреть
концепцию Tutor Mode. Пользователь прислал два альтернативных драфта
промпта (Gemini-промпт из `roadmap.md` и отдельный "AI-тренер" промпт).
По итогам обсуждения — большинство идей из обоих драфтов **отклонены**,
ниже зафиксировано, что реально меняется.

---

## 1. Что НЕ меняется (инварианты)

Чтобы не перепутать с идеями из отклонённых драфтов:

- Личность Mrs. Smith (биография, сад, память между Tutor/Flow/PenFriend) —
  без изменений.
- Архитектура из двух параллельных LLM-вызовов и двух отдельных баблов
  (карточка-коррекция ❌/✅/💡 + ответ Mrs. Smith) — **сохраняется**,
  не объединяем в один вызов/один бабл.
- Коррекция остаётся тихой: карточка никогда не прерывает разговор вслух,
  Mrs. Smith никогда сама не комментирует ошибку в диалоге.
- Голос зеркалит ввод (voice → voice, text → text,
  `VOICE_RESPONSE_MODE=mirror`) — без изменений.
- Recasting (PenFriend) и Mistakes Practice остаются раздельными
  тумблерами в Settings — не сливаем.
- Никаких командных под-режимов ("режим учителя/переводчика/анализа" и
  т.п.) — не добавляем.

## 2. Изменение №1 — память о повторах ошибок в рамках сессии

Сейчас `correct_text()` (`groq_client.py:149`) ничего не знает о
предыдущих сообщениях в этом же разговоре — каждое сообщение оценивается
независимо. Добавляем session-scoped память специально для Tutor Mode.

### 2.1 Границы сессии

**Начало:** нажатие "🎓 Tutor" (`activate_tutor`, `message.py:400`) —
инициализирует/сбрасывает in-memory состояние трекера для этого
`user_id`.

**Конец** — первое из:
1. Явная команда — "⏹ Stop Tutor" (`deactivate_tutor`, `message.py:413`).
2. Переключение на другой режим (Flow/PenFriend/Synonym Streak) без
   нажатия Stop — тоже закрывает сессию.
3. Обнаруженное прощание — переиспользуем существующий
   `groq_client.detect_farewell()` (уже вызывается в `handle_message`,
   `message.py:1005`), которым сейчас триггерится сохранение саммари.
4. Защитный таймаут по неактивности — если с последнего сообщения в
   Tutor Mode прошло больше N часов (предлагается 3–4 часа, обсудить
   финальное число при реализации), следующее сообщение стартует новую
   сессию, а не продолжает старую эскалацию.

### 2.2 Хранилище

In-memory словарь в `message.py`, по аналогии с уже существующими
кэшами (`_originals_cache`, `_summarization_locks` и т.п.) —
персистентность между рестартами процесса не нужна, это сессионные
данные, а не долгосрочная статистика (для долгосрочной уже есть
`error_logs` + Sunday Deep Dive).

Примерная структура на пользователя:
```python
{
    "started_at": <timestamp>,
    "last_message_at": <timestamp>,
    "categories": {"prepositions": 3, "grammar": 1, ...},
    "last_category": "prepositions",   # для правила "не подряд"
    "escalated_categories": {"prepositions"},  # уже прошли эскалацию
}
```

### 2.3 Правила поведения

- Если категория ошибки в текущем сообщении совпадает с
  `last_category` предыдущей карточки — **не показывать карточку**
  повторно для той же категории два раза подряд, если это не системная
  (часто повторяющаяся) ошибка. "Системная" = уже встречалась в этой
  сессии 2+ раза до этого.
- Если категория встретилась **3+ раза за сессию** — карточка меняет
  формулировку: вместо очередного "вот ошибка, вот исправление" —
  тихая просьба самому употребить правильную форму в следующем ответе.
  Помечаем категорию как `escalated`, чтобы не повторять формулировку
  бесконечно на 4-й, 5-й и т.д. раз.
- Разговорный бабл Mrs. Smith (`generate_tutor_response`) по-прежнему
  никак не участвует в этой логике — она полностью в карточке.

### 2.4 Точки в коде

- `groq_client.py:149` `correct_text()` — добавить параметр вида
  `session_categories: dict` (или похожий), скорректировать промпт/
  постобработку под правила выше.
- `message.py:932` `handle_message()` — читать/обновлять
  session-трекер, передавать его в `correct_text` (через
  `process_user_message`), решать текст карточки на основе результата.
- `message.py:400,413` `activate_tutor`/`deactivate_tutor` —
  инициализация/сброс трекера.
- `message.py:1110` (блок `is_farewell`) — сброс трекера при
  обнаруженном прощании.

## 3. Изменение №2 — усиленный End-of-Session review

Текущая реализация: `generate_session_analysis()`
(`groq_client.py:1266`) — три секции (TOPICS DISCUSSED / LANGUAGE
OBSERVATIONS / PROGRESS NOTES), до 200 слов, без реальных примеров
ошибок, без оценки уровня. Используется в `_generate_session_summary_pdf()`
(`message.py:284`), вызывается по кнопке "📄 Session Summary".

### 3.1 Целевая структура (по образцу roadmap.md)

1. **Общий уровень** — примерная оценка (B1/B2/C1 и т.п.) на основе
   разговора.
2. **Типичные/повторяющиеся ошибки** — сгруппированы по категориям
   (грамматика/лексика/стиль), с реальными примерами из сообщений
   пользователя (не выдуманными).
3. **Что уже хорошо получается** — обязательный блок, для мотивации.
4. **Конкретные рекомендации** — что подтянуть дальше, не общие фразы.

### 3.2 Источники данных

Сейчас `generate_session_analysis()` получает только `messages`
(сырой текст сообщений пользователя). Для блока 2 этого недостаточно —
нужны реальные категоризированные ошибки. Предлагается дополнительно
передавать туда данные из `db.get_recent_errors(user_id, limit=10)`
(`supabase_db.py:586`, уже возвращает category/mistake_text/
corrected_text/mastery_score, используется для Mistakes Practice) —
аналогично тому, как `get_weekly_errors_for_report` уже используется
для Sunday Deep Dive.

**Важно:** при реализации блока 2 учесть баг №4 из ревью кода
(`get_weekly_errors_for_report` в `supabase_db.py:541` не прокидывает
`corrected_text` в сгруппированный результат) — для нового Session
Summary этот источник не используется напрямую, но если код будет
переиспользоваться между Sunday Deep Dive и Session Summary, баг нужно
чинить в общем месте, а не дублировать его.

### 3.3 Точки в коде

- `groq_client.py:1266` `generate_session_analysis()` — переписать
  промпт под 4 секции, добавить параметр с данными об ошибках.
- `message.py:284` `_generate_session_summary_pdf()` — обновить PDF-
  вёрстку под новую структуру (сейчас там жёстко зашиты "Transcript" +
  "Session Analysis" как один блок текста).
- Триггер вызова (кнопка "📄 Session Summary", `cq_session_summary`,
  `message.py:355`) — **не меняется**, вызывается так же, по кнопке.

## 4. Вне скоупа этой итерации

Явно НЕ входит в эту спеку (см. `roadmap.md` для полного редизайна):

- Слияние карточки-коррекции и ответа Mrs. Smith в одно сообщение/один
  LLM-вызов.
- Прерывание разговора вслух при повторе ошибки.
- Командные под-режимы (учитель/переводчик/анализ/простое объяснение/
  мысли вслух).
- Голос по умолчанию вместо зеркалирования ввода.
- Слияние Recasting и Mistakes Practice в одну механику.
- Любые баги, найденные при общем ревью кода (пустые re-engagement
  сообщения, paywall на персонажей, "Elementary" уровень и т.д.) — они
  зафиксированы отдельно и не являются частью этой спеки по Tutor Mode.
